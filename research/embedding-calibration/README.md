# Embedding calibration: EmbeddingGemma v1 vs v2 for free-form interest tags

**Purpose.** Grouper lets users type free-form interest tags in Danish or English (`madlavning`, `cooking`, `far på barsel`, `brætspil`). The server embeds each tag, assigns it to an interest *concept* (nearest concept centroid if cosine ≥ the merge threshold, else a new concept), and runs a sensitive-interest detector for GDPR Art. 9 categories (health incl. pregnancy, religion, sexual orientation, politics, ethnic origin, trade union). Pods are themed on a shared concept, so a false merge between a sensitive and an ordinary tag can leak sensitive data.

This folder re-runs the EmbeddingGemma v1 calibration (the `[EXP]` source in `docs/DESIGN.md`) and runs the same analysis for **EmbeddingGemma 2**, with the same test set and the same code, so the numbers can be compared directly. It is the evidence for the M0 gate in DESIGN.md (A1/Q1: "v2 only if it matches v1 on our labelled set").

Run date: 2026-11-04. All numbers below come from `results/*.json`, generated by the scripts in `scripts/`.

## Verdict

**v2 passes the gate. Switch to EmbeddingGemma 2, q4, text-only.**
- **Matching is better.** Recall at ≥ 95% merge precision rises from 0.26 to 0.42. In a paired bootstrap the gain is +0.16 (90% interval +0.03 to +0.32).
- **The detector is no worse.** The detector's pair AUC is 0.955 vs 0.957, and false flags at 100% recall are 46/112 vs 44/112 (paired difference not significant).
- **Danish/English behaviour is much better** (details under Findings).
- **Licence:** Apache-2.0 instead of the Gemma Terms of Use.
- **The cost is speed and memory.** v2 q4 is 1.7–2.1× slower per tag than v1 q4 on CPU, and peak memory is about 130 MB higher.

All thresholds must be re-derived for v2. Its cosine scores sit in a narrow, high band, and none of the v1 thresholds carry over.

## Findings, including the surprises

1. **The v1 results reproduce exactly.** The v1 embeddings are bit-identical to the earlier experiment, and every reported v1 number comes back. AUC 0.832; 0.86 → P 0.952 / R 0.306; detector −0.03 → 44/112 false flags; τ 0.85 → 155.2 clusters, B³ 0.95 / 0.455, 2.2 mixed clusters. A clean-room run (`npm ci` from the lockfile, fresh embeddings) reproduces all six result files byte-for-byte, apart from timing fields.
2. **Narrow band and a precision cliff.** In v2, every tag's best-centroid score is ≥ 0.866 (p05 0.882; v1: min 0.709), so the whole decision happens between about 0.87 and 0.95. Precision jumps from 0.89 to 0.99 between 0.92 and 0.93. v1's 0.86 threshold would give P 0.70 in v2. Thresholds need 0.005 resolution. Any change of model revision, dtype or runtime needs re-calibration; q4/q8/fp32 happen to share 0.925 here.
3. **v2 q4 is slower than v1 q4**, even though it is smaller (270M vs 300M parameters, 174 vs 197 MB). Single-tag p50 is 25.5 vs 15.0 ms at 4 threads and 64.6 vs 30.7 ms at 1 thread; peak RSS is 680 vs 547 MB. That is still fine for an online tag request. q8 is 5× slower than q4 for single tags in **both** models (ORT CPU, dynamic-quantised MatMul). q4 is the only sensible CPU choice. The earlier probe's "v2 q4 74 ms" (1 thread) matches the 64.6 ms measured here.
4. **Online clustering is fragile at low τ in v2.** Tags sit in a narrow cone: cos(tag, global mean direction) has p50 0.903 and max 0.93. So a running centroid that absorbs a few diverse tags drifts toward the common direction and attracts everything. At τ ≤ 0.86 v2 forms 1–12 clusters; each −0.01 step between 0.90 and 0.87 merges 23–38 clusters. At τ 0.93 this is safe on this set. But production concepts will be much larger than the test set's (≤ 13 tags), so monitor how big concepts get and how many tags join them. Global mean-centring removes the collapse: about 3 clusters per 0.01 of τ instead of 12–38, with similar B³ at matched precision.
5. **Cross-sensitivity false pairs persist and some are worse.**
   - In v2: Christiania~christian 0.944 (v1 0.898), kirkekor~kirkegænger 0.936, baking~diabetes-friendly baking 0.929, yoga~graviditetsyoga 0.924, maternity leave~pregnant 0.912.
   - At the P ≥ 0.95 threshold, christian→Christiania and graviditetsyoga→yoga are wrong auto-merges.
   - At τ 0.93, online clustering produces {Christiania, christian, kristen} and {kirkekor, kirkegænger}.
   - At lower τ (0.89) v2 forms broad topical clusters that pull sensitive tags into ordinary ones: klimaaktivisme into a sports cluster, Somali community with international community, buddhist with meditation, halal and diabetes-friendly baking with cooking.
   - The guard (never merge across the detector flag) leaves 0 leaking clusters; the remaining mixed clusters over-protect a non-sensitive tag (e.g. Christiania gets flagged).
6. **v1's Danish surface-form confusions are weaker but not gone.**
   - Measured as the percentile among all unrelated pairs: brystkræft~brætspil fell from the 100th to the 97.7th percentile (0.857) and madlavning~fagforening to the 89.6th (0.838).
   - havearbejde~frivilligt arbejde (0.896, 99.8th) and sprogcafé~strikkecafé (0.904, 99.9th) are still near the top. They stay below the 0.93 merge threshold, so they no longer form clusters at τ 0.93 (v1 formed both at τ 0.87).
   - Overall, unrelated da–da and en–en means are now equal (0.817 / 0.816), and cross-lingual translations rose from mean 0.78 to 0.91. Weakest translation pairs: healthy eating~sund kost 0.822, sober~ædru 0.826.
7. **Mean-centring is not needed for matching any more.**
   - Global centring raises pair AUC (0.870 → 0.908) but lowers recall at the high-precision end (0.415 → 0.326) and nearest-neighbour top-1 (0.777 → 0.741).
   - Per-language centring needs language ID and still has lower recall (0.373).
   - v1's reason for centring (Danish bias of 1.17 sd) has disappeared in v2 (0.05 sd).
   - For the detector, centring changes nothing significant (AUC 0.955 → 0.953).
8. **The detector did not improve, and it carries a Danish cost.**
   - Margin AUC is the same as v1, and so is the false-flag count at 100% recall (46 vs 44 of 112).
   - The hardest true positives are now ufrivilligt barnløs (closest anchor is `frivilligt`, still a Danish substring effect), iftar under ramadanen (closest to "food and drink"), døv, bøsse (`bøn` vs `bøger`) and kørestolsbruger.
   - Because those are Danish, the 100%-recall threshold falsely flags **64% of Danish hobby tags but 16% of English ones** (v1: 68% vs 12%). The tags hit most are new-parent tags (mødregruppe, fædregruppe, nybagt far/mor, barselsorlov), korsang, meditere and baking.
   - Danish users will therefore get far more consent prompts. The next lever is better Danish hobby anchors and prototypes plus the lexicon; this run deliberately did not change them, to keep the comparison with v1 fair.
9. **The content-template prompt again has the best AUC** (`… query: A group of people who share an interest in <tag>`, 0.913). But its P ≥ 0.95 threshold sits at 0.965 with lower recall (0.368), so it is not recommended.
10. **q4 is closer to fp32 in v2 than in v1**, even measured relative to v2's narrower band: pairwise drift 0.22 vs 0.46 sd, and minimum vector cosine to fp32 0.959 vs 0.904.

## Caveats (read before using the numbers)

- **The test set is small and self-labelled.** 211 tags, 68 concepts (18 with a single tag), 71 clearly sensitive, 112 non-sensitive and 28 ambiguous tags (reported separately). One labeller. Some labels are debatable (`amb` notes in `data/testset.mjs`). One tag moves precision or recall by 1–2 points.
- **Thresholds are tuned in-sample.** The concept-level bootstrap estimates the optimism. For the merge threshold, out-of-bag precision is about 0.955 and recall about 0.40. For the detector, the in-sample "100%" threshold gives about 97.6% recall on unseen concepts. Re-validate on real, consented tags once they exist, and re-calibrate after the first few thousand.
- **"100% recall" depends on one tag.** The FP count at that point is set by the single hardest positive. Prefer the AUC and the bootstrap numbers when comparing models.
- **The detector depends on the hand-made prototype and anchor lists** in `data/testset.mjs`. They were kept identical to v1 so the comparison is fair, not because they are optimal.
- **Latency is indicative only.** It was measured on a shared 4-vCPU Xeon @ 2.30 GHz sandbox VM with Node 22.23.4, `@huggingface/transformers` 4.3.2 and `onnxruntime-node` 1.30.0. Values are medians of 3 interleaved repetitions (fp32 and v1 q8: 1 repetition); one v2 q8 repetition was noisy (203 ms). This is not Cloud Functions. The earlier v1 run used a 2.10 GHz host, so v1 was re-measured here (v1 q4 15.0 ms now vs 15.5 ms then).
- **Other runtimes are untested.** Mobile ONNX, WebGPU, wasm and fp16 variants were not run. Quantised kernels differ per platform, so re-verify thresholds before running the detector on-device (DESIGN Q18).
- **v2 is young.** The ONNX repo was created on 2026-10-04 and last changed on 2026-10-06. Pin the revision.
- **Node version.** The repo root requires Node ≥ 24.12. This standalone folder (not an npm workspace) was run on Node 22.23.4 and has not been tested on 24.

## Reproduce

Requirements: Node ≥ 22.12, bash, curl, sha256sum, about 3 GB of disk for the models and 750 MB for `node_modules`. Python with `tokenizers==0.22.1` is needed only for the optional tokenizer cross-check. Run everything from this folder:

```bash
cd research/embedding-calibration
npm ci                      # @huggingface/transformers 4.3.2 (pins onnxruntime-node 1.30.0); lockfile included

# 1. models at pinned revisions; every LFS file is sha256-checked against the Hub manifest for that revision
bash scripts/download-model.sh onnx-community/embeddinggemma-300m-ONNX 5090578d9565bb06545b4552f76e6bc2c93e4a66 q4 q8 fp32
bash scripts/download-model.sh onnx-community/embeddinggemma-2-ONNX   daa72c51243991dfcaf9f9137d2c573d8f7790c0 q4 q8 fp32

# 2. sanity check: text-only load, unit-norm output, model-card reference scores
node scripts/smoke.mjs v2 q4    # expect "card example 768d 0.684 0.854 0.752 0.783" and "256d 0.706 0.871 0.775 0.807"

# 3. embeddings: 211 tags + 110 prototypes + 32 anchors + lowercase variants (379 unique texts), x 7 prompts -> out/emb_<model>_<dtype>.bin
for r in v1:q4 v1:q8 v1:fp32 v2:q4 v2:q8 v2:fp32; do node scripts/embed.mjs ${r%%:*} ${r##*:}; done

# 4. perf (quiet machine; one process per measurement) -> out/perf_*.json
for rep in 1 2 3; do for th in 4 1; do for r in v1:q4 v2:q4 v2:q8; do
  node scripts/embed.mjs ${r%%:*} ${r##*:} --perf --threads $th --rep $rep; done; done; done

# 5. analysis per run -> results/<model>-<dtype>.json   (about 15 s each)
npm run analyze             # = node scripts/analyze.mjs <model:dtype> --ref <model>:fp32 for all six runs

# 6. comparison table + paired bootstrap -> results/comparison.md, results/comparison_v2q4_vs_v2q8.md
npm run compare

# optional: transformers.js token ids vs the reference Rust tokenizer (0 mismatches for both models)
node scripts/tokcheck_dump.mjs v2 && python3 -I scripts/tokcheck.py models/onnx-community/embeddinggemma-2-ONNX/tokenizer.json out/token_ids_v2.json
```

`bash scripts/run-all.sh` runs steps 1–6 in one go (`SKIP_PERF=1` skips step 4). The models are read with `env.allowRemoteModels = false`, so a run can never silently pull a different revision.

## Method (short)

- **Test set** (`data/testset.mjs`, unchanged from v1). Each tag has a language, a fine concept (the merge target), a coarse family, and an Art. 9 category or null. It also includes 110 sensitive prototype phrases (none identical to a test tag; checked) and 32 generic hobby anchors in Danish and English (31 unique).
- **Pair AUC.** Same-concept vs different-concept pairs; 22,155 pairs in total.
- **Leave-one-out (LOO) assignment.** Each tag is removed from its concept and assigned to the nearest concept centroid. Precision counts merges into the wrong concept, including merges of tags whose concept has no other member. Recall is correct merges divided by tags that have a home. The "stable rule" threshold is the lowest grid value (0.005 steps) from which precision stays ≥ 0.95 at every higher threshold with ≥ 5 merges.
- **"Did you mean" band.** Precision among tags whose best score falls in [lo, merge threshold).
- **Detector.** margin = max cos to prototypes − max cos to anchors (a tag is never compared with an identical anchor). Thresholds use a 0.001 grid: the highest value that still reaches the recall target, scored on clear (non-ambiguous) tags.
- **Online clustering.** Tags arrive in 5 random orders and join the nearest running centroid if cosine ≥ τ. Scored with B³ precision/recall against the concepts. The guard variant never merges across the detector flag.
- **Bootstrap.** Resample the 68 concepts with replacement, re-pick each threshold on the in-bag tags, and evaluate on the out-of-bag concepts. Paired comparisons use the same resamples for both models.
- **Mean-centring.** Global: subtract the mean of the 211 tag vectors, then re-normalise. Per-language: subtract the mean per `da`/`en`/`x`, using the label language as an oracle.
